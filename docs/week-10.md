## 디버깅 요청 4요소 / Four parts of a debugging request

- 증상 Symptom: 2주차 `trip-seed` 수락 테스트가 끝나지 않고 멈춤
- 재현 Steps: 테스트 환경을 구성하고 `acceptance.test.js`를 실행
- 기대 Expected: 테스트 9개를 실행한 뒤 프로세스가 종료됨
- 실제 Actual: 시드의 `db.js`가 별도의 연결 풀을 열고 닫지 않아 프로세스가 종료되지 않음. 테스트와 같은 연결 풀을 쓰도록 바꿔 해결함

## **버린 기능과 이유 / Features dropped and why**

- 숏폼 일정 빌더: 영상 데이터를 확보할 수 없음
- 게임화·미니룸, 금전 보상: 구현 기간이 부족하고 학생 프로젝트에서 보상을 제공할 수 없음
- 자동 비행 정보 조회: 항공 데이터 API가 대부분 유료임
- 해외 여행 지원: 지도 SDK를 두 개 유지해야 하므로 국내로 한정함



## 데모 시나리오 초안 / Draft demo scenario

"3명이 제주 2박 3일을 계획하는 상황"을 기기 2대로 시연한다.

1. 방장이 여행방을 만들고 다른 기기에서 초대 코드로 참여한다.
2. 채팅으로 날짜, 출발지, 이동수단, 예산을 이야기한다.
3. 조건 확인 화면에서 추출된 조건과 출처 메시지를 보여 준다.
4. 조건에 맞는 여행지 3곳을 추천받는다.
5. 일부러 표가 갈리게 투표한 뒤 과반 득표 여행지를 확정한다.
6. 공동 일정표에 장소를 추가해 다른 기기에 바로 반영되는 것을 보여 준다.
